# API Mail

[English](reference.md)

MetaPaaS публикует API по пути `/v1/types/mail/`. Авторизация использует
Bearer-токен. Доступ к экземплярам и их дочерним ресурсам определяется
правами в проекте. Полный пример запроса для экземпляра приведён в
[руководстве по развёртыванию](../usage/deployment.ru.md).

| Метод | Путь относительно `/v1/types/mail/` | Операция |
| ----- | ------------------------------------ | -------- |
| GET | `versions/` | Получить список версий образов и сведения о поддержке mailbox |
| GET | `versions/{version_uuid}` | Получить версию образа |
| GET, POST | `instances/` | Получить список или создать экземпляр |
| GET, PUT, DELETE | `instances/{instance_uuid}` | Прочитать, изменить или удалить экземпляр |
| GET, POST | `instances/{instance_uuid}/accounts/` | Получить список или создать учётную запись SMTP |
| GET, PUT, DELETE | `instances/{instance_uuid}/accounts/{account_uuid}` | Прочитать, изменить или удалить учётную запись SMTP |
| GET, POST | `instances/{instance_uuid}/mailboxes/` | Получить список или создать ящик |
| GET, PUT | `instances/{instance_uuid}/mailboxes/{mailbox_uuid}` | Прочитать или изменить ящик |

## Экземпляры

Задайте `domain`, `mode` и `version` при создании. Режим по умолчанию —
`smtp_only`. Версия с `supports_mailbox: true` поддерживает оба режима.
Укажите версию ссылкой на ресурс, например
`/v1/types/mail/versions/{version_uuid}`. Количество vCPU, объём ОЗУ в
МиБ и размер диска данных в ГиБ меняются через `cpu`, `ram` и
`disk_size`. Диск можно увеличивать. Минимумы CPU и ОЗУ для
`mailbox` действуют и при изменении ресурсов.

Поля `status`, `ipsv4`, `endpoints`, `dkim_public_key` и `dkim_selector`
доступны только для чтения. В режиме `mailbox` поле `endpoints`
содержит `submission`, `imap`, `caldav` и `inbound_relay`. В режиме
`smtp_only` оно содержит `submission`.

## Переключение режима

Отправьте `PUT /v1/types/mail/instances/INSTANCE_UUID` с `{"mode":"mailbox"}`
или `{"mode":"smtp_only"}`. Если для `mailbox` нужно больше ресурсов,
передайте `cpu` и `ram` в том же запросе. Изменение применяется на
существующей ВМ. Дождитесь статуса `ACTIVE` перед подключением.

Postfix TX перезапускается, сохраняя очередь, ключ DKIM и сертификаты.
Учётные записи SMTP работают в обоих режимах. В `smtp_only` данные
ящиков остаются на томе, а учётные записи — в MetaPaaS. Вход в ящики
и приём писем приостанавливаются. При возврате в `mailbox` ящики и их содержимое
снова доступны. Внешний MX может держать очередь и повторять доставку.

## Учётные записи SMTP

Учётные записи SMTP доступны в обоих режимах для отправки писем. При
создании передайте `username`, `password`, `project_id` и ссылку
`instance`. Имя задаётся при создании. Чтобы отключить вход, установите
`active: false`. ВМ применяет изменения асинхронно.

Передавайте пароль по HTTPS. Для совместимости `smtp_only` принимает
в `password` готовый хеш crypt, например SHA512-crypt с необязательным
префиксом `{SHA512-CRYPT}`. Передайте готовый хеш, если сам пароль
начинается с `$` или префикса схемы crypt. Для учётной записи в режиме `mailbox`
передавайте пароль без хеширования. Поле `password` доступно только для
записи, `password_hash` скрыто.

## Почтовые ящики

Ящик принадлежит проекту своего экземпляра в режиме `mailbox`.
Используйте следующий JSON для запроса к коллекции `mailboxes/` экземпляра.

```json
{
  "instance": "/v1/types/mail/instances/INSTANCE_UUID",
  "project_id": "PROJECT_UUID",
  "local_part": "alice",
  "owner_user_uuid": "USER_UUID",
  "aliases": ["sales"],
  "password": "REPLACE_WITH_A_GENERATED_PASSWORD"
}
```

`local_part` задаётся при создании. Для локальных имён используйте
строчные латинские буквы, цифры, подчёркивания и дефисы. Начинайте имя
с буквы или цифры и используйте до 64 символов. Основное имя
и алиасы должны быть уникальны среди ящиков и учётных записей SMTP
экземпляра. Сервер вычисляет `address` и `status`. Для смены пароля
передайте новое значение `password`, при остальных обновлениях
опускайте это поле.

Поля `owner_user_uuid`, `aliases` и `active` можно обновить. Когда
`active` выключен, ящик сохраняет письма и продолжает принимать
почту. После применения изменений вход по SMTP, IMAP и CalDAV
отключается.
