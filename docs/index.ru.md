# Exordos Mail

[English](index.md)

Mail — элемент `mailaas` для MetaPaaS. Каждый экземпляр получает одну ВМ.
Оба режима используют один образ. Режим по умолчанию `smtp_only` подходит для отправки писем из приложений.
Режим `mailbox` добавляет приём писем, почтовые ящики и календари.

## Архитектура

Контур управления MetaPaaS хранит экземпляры, версии образов, учётные
записи SMTP и метаданные ящиков. Он создаёт ВМ через Core. Агент на ВМ
применяет учётные записи, алиасы и данные для входа. В режиме `smtp_only`
на ВМ работает Postfix TX. Для входа по SMTP он использует отдельный
сокет аутентификации Dovecot. В режиме `mailbox` на той же ВМ работают следующие
systemd-сервисы.

- Postfix RX принимает почту для настроенного домена на приватном
  TCP-порту 2525 с STARTTLS. Почта передаётся в Cyrus через локальный
  сокет LMTP.
- Rspamd проверяет SPF, DKIM, DMARC и признаки спама у входящих писем.
  Данные байесовского фильтра и история проверок хранятся в локальном
  Valkey.
- Cyrus предоставляет IMAP и CalDAV, хранит письма и календари на
  диске данных и использует локальные базы и файлы.
- У Postfix TX отдельная очередь и системный пользователь. На порту 587 он проверяет
  учётные данные, сверяет адрес отправителя конверта и заголовок
  `From` с разрешёнными адресами и подписывает письма DKIM.

```text
Интернет -> внешний MX:25 -> приватный RX:2525 -> Cyrus
                               |
                               +-> Rspamd -> Valkey

Почтовый клиент -> TX:587 -> MX получателя (внешние домены)
                      |
                      +-> приватный RX:2525 (локальный домен)
Почтовый клиент -> Cyrus:993 (IMAP), Cyrus:8443 (CalDAV)
```

Публичный MX можно разместить в другой сети или у другого провайдера.
У каждого MX своя очередь на диске. Когда ВМ с ящиками недоступна,
внешние MX сохраняют принятые письма и повторяют доставку. Доступ к
ящикам и отправка писем по-прежнему зависят от доступности этой ВМ.
