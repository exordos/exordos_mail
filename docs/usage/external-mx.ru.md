# Внешний MX

[English](external-mx.md)

Разверните одну или несколько отдельных ВМ с Postfix. Для каждой
нужны публичный TCP-порт 25, локальный Milter Rspamd, постоянный диск
с точкой монтирования `/var/spool/postfix` и приватная связность с
`inbound_relay` экземпляра на порту 2525. Оставьте порт RX в приватной
сети. MX можно разместить в другом облаке при наличии такого маршрута.

## Маршрут до RX

Возьмите конфигурацию из примера и задайте для каждого домена маршрут
к приватному адресу RX. Имя следующего узла должно разрешаться в
приватный адрес и совпадать с именем сертификата RX (по умолчанию
`mail.<домен>`). MX предлагает отправителям STARTTLS и требует TLS с
проверкой сертификата при доставке на RX. Скопируйте сертификат CA
в файл `/etc/postfix/tls/rx-ca.pem` на MX. См.
[пример Postfix и команды установки](https://github.com/exordos/exordos_mail/tree/master/examples/external-mx).

Включите на MX проверки SPF, DKIM и DMARC. Запишите каждый выделенный
IP источника MX, который видит RX, отдельной строкой в
`/persist/mail/control/trusted-mx` и перезапустите
`exordos-mail-rspamd.service`. RX сам проверяет SPF, DKIM и DMARC и применяет политику отклонения DMARC отправителя.
Если письмо пришло с доверенного IP MX, Rspamd берёт для SPF
исходный IP отправителя из заголовка `Received` этого MX. Для
остальных подключений он использует IP SMTP-соединения.

MX принимает адресатов настроенных доменов без списка ящиков. RX
доставляет письмо известным локальным адресатам и отбрасывает
неизвестных по одному без уведомлений, в том числе в письме с несколькими
адресатами.

## Очередь и повторная доставка

Конфигурация из примера резервирует 1 ГиБ свободного места на диске
очереди, принимает письма до 25 МиБ и повторяет доставку до пяти дней.
Интервал повторных попыток Postfix начинается с пяти минут и растёт до
часа. У каждого MX своя очередь.

- Используйте `postqueue -j`, чтобы увидеть отложенные письма. Следите
  за их возрастом, размером очереди и свободным местом на каждом узле.
- После восстановления RX выполните `postqueue -f` на каждом MX для
  немедленной повторной попытки доставки.
- Если срок хранения подходит к концу, удержите нужные письма через
  `postsuper -h QUEUE_ID`. После восстановления снимите удержание
  командой `postsuper -H QUEUE_ID`. После долгой паузы верните письмо в
  очередь через `postsuper -r QUEUE_ID`.

В примере настроена доставка только на внутренний RX. Для отправки
уведомлений о недоставке внешним отправителям понадобится отдельный
маршрут. Проверьте очередь до публикации MX. С приватного тестового
сервера отправьте письмо на известный ящик при недоступном RX,
убедитесь, что оно появилось среди отложенных, и проверьте доставку
после восстановления RX.
