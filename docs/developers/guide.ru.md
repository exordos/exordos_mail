# Руководство разработчика

[English](guide.md)

## Сборка и тесты

```bash
make build       # Собрать wheel, общий образ ВМ и манифест элемента
make test        # Запустить юнит-тесты
make lint        # Проверить Python через Ruff
make format      # Отформатировать Python-код
make typecheck   # Проверить типы через mypy
```

Элемент устанавливает wheel, опубликованный вместе с его сборкой.
Для проверки локальной сборки опубликуйте её в репозитории элементов,
доступном тестовому Realm, и установите полученную версию.

Запускайте функциональные тесты на изолированном Realm с Core,
MetaPaaS и установленным `mailaas`. ВМ должны быть доступны с машины,
запускающей тесты. Перед запуском задайте `EXORDOS_PASSWORD` в окружении.

```bash
EXORDOS_ENDPOINT=http://10.20.0.2/api/core \
EXORDOS_USERNAME=admin \
EXORDOS_MAIL_CP_URL=http://10.20.0.2/api/metapaas \
make functional
```

Функциональные тесты проверяют API и вход по SMTP и переключают
экземпляр между обоими режимами. Для проверки внешнего MX используйте
приватный тестовый домен, локального SMTP-отправителя и получателя.

## Структура репозитория

| Путь | Содержимое |
| ---- | ---------- |
| `exordos_mail/controlplane/` | API, модели, настройка инфраструктуры и сервиса |
| `exordos_mail/dataplane/` | Применение учётных записей и ящиков на ВМ |
| `exordos_mail/migrations/` | Миграции базы контура управления |
| `exordos_mail/tests/` | Юнит-тесты и функциональные тесты |
| `exordos/images/` | Скрипты сборки образов, начального запуска и настройки |
| `exordos/manifests/` | Манифест элемента и пример его использования |
| `etc/systemd/`, `etc/mailbox/` | Сервисы systemd и шаблоны конфигурации mailbox |
| `examples/external-mx/` | Конфигурация Postfix для внешнего MX и инструкция |

## Начальная настройка ВМ

Bootstrap подготавливает диск данных и подключает `/var/log` через
bind mount. Сервис настройки запускается после bootstrap, поэтому
bootstrap ставит его запуск в очередь через `systemctl --no-block`.
Сервис настройки ожидает `mail.env` от агента рендеринга и проверяет
точки монтирования `/persist` и `/var/log`. Оба агента остаются
доступны для диагностики и восстановления при сбое подготовки диска.
После устранения сбоя агент может повторить настройку.

Юнит-тесты запускают скрипт bootstrap с подставными командами.
Первое включение, фактический порядок запуска systemd и обновления
с заменой корневого образа проверяйте на изолированном Realm.

## Документация

Используйте Python 3.12 и tox с tox-uv.

```bash
uv tool install tox --with tox-uv
tox -e docs
tox -e docs-build
```

Локальный просмотр доступен по адресу `http://127.0.0.1:8181`.
Сборка сохраняется в `site/`. При изменении страницы обновите
английский Markdown-файл и его версию с суффиксом `.ru.md`.
Документация проверяется на pull request. Сборка из master может
публиковаться в GitHub Pages, если выбран источник GitHub Actions.
